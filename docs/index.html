A poker table where each AI seat is played by a language model with its own personality — a maths-first grinder, a hyper-aggressive maniac, an ultra-tight nit, a deceptive trickster. Underneath sits a from-scratch rules engine with real side pots, split pots and strict chip conservation.

What makes it different

Most poker bots are a lookup table wearing a hat. The interesting part here is that each seat is given the whole public picture and asked to reason about it in character.

🃏

A real rules engine

Side pots, split pots, uncalled-bet refunds, heads-up blind order, all-in run-outs. Chip conservation is asserted event by event across full games.

🎭

Characters, not clones

Seven hand-written personas, each with a system prompt, a voice and four behavioural tendencies. Or write your own in the UI.

🧠

Full public context

Position, the ordered betting history of the hand, effective stacks and SPR, recent hands with their showdowns — plus a legal-action menu it cannot cheat past.

🤐

Table talk stays honest

Models may bluff in words, but never describe a hand. The prompt says so, and a filter drops any line that does it anyway.

👁️

God mode as a switch

Flip it to see every hole card and every thought. It is display-only: the prompts never contain another seat's cards.

🧪

Audited, not just tested

A rule fuzzer, an independent hand-evaluator cross-check, and a bot audit. The engine bugs found so far were all found by the fuzzers.

Why it was rewritten

The original code had a working skeleton, but the poker itself was wrong in ways that quietly corrupted games. A sample of what was fixed — each one is covered by a test today.

BugConsequenceFix
No side pots at all An all-in player could win chips they never matched Layered pots with per-layer eligibility
Uncalled bets never returned A shove nobody could call vanished into the pot Uncalled excess is refunded
Split pots picked a winner The first player in seat order took tied pots Even split; odd chip to the first winner left of the button
Betting loop used a stale player list A player who called could be skipped entirely Action closure by what each seat still owes
Model output injected straight into the game Any illegal reply aborted the hand A legality firewall: models choose from an engine-computed menu
A missing API key killed the game No key meant no game at all Retry, then a legal fallback; no key degrades to a local bot

How it fits together

The rules layer has no dependencies — it is importable and testable anywhere. Everything that needs a network or a UI sits on top of it. 

# pure standard library: no network, no framework, no C extensions
pokerarena/
  cards.py      bitmask 5/6/7-card evaluator, deck, card
  engine.py     betting closure, side pots, street flow, table state
  pot.py        pot layering, refunds, split payouts
  strength.py   hand ranking, and equity against a range

# the characters
  personas.py   templates, tendencies, voice; operator-defined personas
  ai.py         prompt assembly, reply parsing, the table-talk filter
  arena.py      seats, blinds schedule, hand loop, history

# the front ends
  web.py        Flask endpoints for the browser table
  web_state.py  session, replay, pause/step, god mode, the result hold
  cli.py        the terminal table
The engine cannot be talked into an illegal move. A seat is handed the exact menu of what is legal, and its answer is re-validated on the way in. A model can return nonsense; the hand keeps going.

Run it locally

Python 3.11+. The rules engine and the offline opponent need nothing but the standard library. 

# clone and install
git clone https://github.com/jiale-wangOwO/LLM-Poker-Arena.git
cd LLM-Poker-Arena
pip install -r requirements.txt

# watch three personas play -- no API key needed
python main.py --demo

# sit down yourself, with real models
python main.py --me --models deepseek-flash

# the browser table
python -m pokerarena.web --port 8080
# then open http://127.0.0.1:8080

Adding a model

Any OpenAI-compatible endpoint works. In the browser UI, open Settings → Providers and paste a base URL, a model name and a key; the key is stored in providers.json on your machine and is never returned by any endpoint. The terminal UI reads keys from .env instead — copy .env.example to start.

Windows note: if a system HTTP proxy is configured, add 127.0.0.1 to NO_PROXY, or local requests may be routed through it and fail.
